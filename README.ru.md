# docsguard

[English](README.md) · **Русский**

Сторож документации – это проверка, которая держит документацию репозитория честной. У каждого
зарегистрированного инструмента есть строка в таблице? Переменные окружения, которые читает код,
где-то описаны? Зеркальный README всё ещё совпадает со страницей, с которой снят? Короткие
аннотации всё ещё называют то, что перечисляет главная страница? Рано или поздно такой сторож
заводится в каждом репозитории, и под ним каждый раз оказываются одни и те же шесть читателей.

Этот пакет – те самые шесть читателей и проверки, которые везде выходят одинаковыми. За
репозиторием остаётся своё: таблица позиций, где лежат его страницы, конфигурация сайта и
манифест, и проверки про его собственный предмет.

Пакет написан после того, как одна и та же проверка была сделана трижды в трёх репозиториях.
Копии успели разойтись. Одна при чтении страницы снимала служебные примечания генератора,
соседняя их оставляла. Один и тот же дефект в одном репозитории был находкой, а в другом
тишиной.

## Установка

Сторож работает на CI и пользователю не отдаётся, поэтому ставится из git, а не выпускается.
Ставят его по тегу, а не по ветке:

```
pip install git+https://github.com/keyfire/docsguard@v0.8.0
```

Потребитель, привязанный к `@main`, получает сделанную здесь правку посреди собственной
проверки. Красную проверку, которой никто не просил, никто и не читает. Привязка к ветке ещё и
оставляет порядок слияния в памяти: сначала общий пакет, потом потребитель. Тег превращает этот
порядок в строчку пул-реквеста самого потребителя, где её читают и проверяют.

Закреплённую версию поднимают в три шага.

1. Правка попадает сюда. `__version__` и строки установки выше поднимаются одним коммитом.
   Сторож валит проверку, если они разошлись, поэтому забыть можно только оба сразу.
2. `main` получает аннотированный тег `v<версия>` сразу после слияния.
3. Каждый потребитель поднимает закреплённую версию до этого тега своим пул-реквестом.
   Здешняя правка валит проверку там, где её и попросили.

## Как пользоваться

```python
from pathlib import Path

from docsguard import Layout, PitchItem, pitch_problems, run, site_description

LAYOUT = Layout(
    root=Path(__file__).resolve().parent.parent,
    site_config=Path(__file__).resolve().parent.parent / "site" / "config.ts",
    pyproject=Path(__file__).resolve().parent.parent / "pyproject.toml",
)

ITEMS = (
    PitchItem("Reports", "Отчёты", "report", "отчёт"),
    # Строка без слов – заголовок, сознательно оставленный вне аннотаций.
    # Причина пишется рядом с ним.
    PitchItem("Steps", "Шаги", None, None),
)


def check_annotations():
    return pitch_problems(ITEMS, headlines(), surfaces())


raise SystemExit(run([check_annotations, check_tools, check_environment]))
```

## Что внутри

- **`Layout`** хранит позиции одного репозитория: корень, каталог документации, конфигурацию
  сайта, манифест. Его принимает каждая функция, поэтому знание о конкретном репозитории
  остаётся в одном литерале.
- **Читатели страницы.** `page_body` отдаёт страницу без frontmatter и примечаний генератора,
  `section_body` – тело одного раздела. `headings` собирает заголовки одного уровня,
  `box_headlines` – жирные заголовки пунктов списка. `front_description` читает описание из
  frontmatter, `lede` – первый абзац прозы. `injected` достаёт блок, который скрипт
  зеркалирования пишет между своими маркерами, а `mirror_source` – корневой документ в том
  виде, в каком его несёт зеркальная страница. `site_pages` перечисляет страницы, которые сайт
  публикует на самом деле. `IMAGE` – шаблон, которым читают ссылки на картинки. Репозиторий,
  который судит свои картинки сам, берёт шаблон отсюда и читает их так же, как здешние
  проверки.
- **Аннотации.** `site_description` и `pyproject_description` читают однострочники, которые
  цитируют вместо страницы: мета-описание сайта и строку-сводку упаковочного манифеста.
  `pitch_problems` сверяет их с блоком возможностей и с собственной таблицей репозитория из
  строк `PitchItem`. Сверяются оба направления, поэтому исчезнувшая возможность не заставляет
  сторожа требовать слово для себя.
- **Утверждения.** `Claim`, `claim_text`, `claim_texts` и `claim_problems` держат один факт в
  одной формулировке сразу в нескольких документах и в комментариях кода. Каждое названное
  таблицей место обязано этот факт высказывать. Прежняя формулировка не должна встречаться нигде
  из просмотренного, причём ровно в том написании, какое у неё было. Сама таблица остаётся в
  репозитории: какие утверждения важны и какими словами – знание о предмете, а не о сторожении.
- **Проверки зеркал.** `mirror_problems`, `injection_problems`, `image_problems` и
  `translation_problems`.
- **Покрытие.** `coverage_problems` сравнивает то, что предлагают исходники, с тем, что
  перечисляет документ: инструменты, которые регистрирует MCP-сервер, переменные, которые читает
  код, имена, которые экспортирует пакет. Эту разность множеств каждый репозиторий писал руками,
  и не по одному разу внутри одного файла. Здесь тоже сверяются оба направления. Пустое
  множество со стороны исходников – находка сама по себе: иначе читатель, переставший
  что-либо находить, проходил бы молча.
- **Соглашения исходников.** Два правила, которых не заметит ни один тест возможности. Оба
  читаются через `ast`, и оба оставляют перечень каталогов потребителю.
  - `process_encoding_problems` следит за кодировкой запущенного процесса, под ним
    `python_sources`, `process_starts`, `asks_for_text` и `encoding_problems`. Процесс, вывод
    которого читают как текст, обязан называть `encoding="utf-8"`. Иначе вывод декодируется
    кодовой страницей машины, и отказ выходит молчаливым: текст возвращается символами замены,
    а код возврата продолжает говорить, что всё прошло хорошо. Правило читают через `ast`, а не
    поиском: вызов, с которого всё началось, написан как `(run or subprocess.run)(...)`, и
    поиск по тексту вызова смотрит мимо него.
  - `text_write_newline_problems` следит за переводом строки в записанном файле, под ним
    `text_writes`, `writes_text` и `newline_problems`. Текстовый файл, записанный без
    `newline=""`, забирает перевод строки платформы. Генератор, переписавший страницу на
    Windows, отдаёт тогда файл, в котором изменилась каждая строка. В рабочей копии с
    `core.autocrlf=input` этого не видно, а на машине без такой настройки весь файл уезжает в
    публичный репозиторий одной сменой окончаний. Каталогов это правило берёт меньше, чем
    соглашение о процессах: то, что пишет тест, ложится во временный каталог и не переживает
    запуска.
- **Жаргон.** `jargon_problems` читает русские страницы репозитория и называет транслитерацию
  там, где есть русское слово. Словарь – это `JARGON`, строка `JargonWord` на слово. В строке
  корень, по которому слово узнают, имя, которым строку выключают, и русское слово взамен. Своё
  слово репозиторий добавляет строкой, а нужное его предмету выключает по имени. Имя, за которым
  в словаре больше нет строки, называет `empty_exceptions`. В словаре двадцать одно слово: `пин`,
  `прогон`, `базлайн`, `хук`, `фолбэк`, `фикс`, `билд`, `дефолт`, `эксепшн`, `апдейт`, `скоуп`,
  `ворктри`, `скаффолдинг`, `воркспейс`, `воркфлоу`, `дашборд`, `бэкенд`, `лаунчер`,
  `мейнтейнер`, `топ-объект`, `легаси`. Список переписан 12.09.2026 по живому чтению, а не по
  теории: слово, мимо которого читатель проходит не переводя, из словаря ушло, а осталось то, на
  чём он спотыкается. Шесть последних пришли из документации инструментов днём позже.
  `jargon_findings` судит один текст и цитирует слово в том виде, в каком оно на странице: так
  его найдёт поиск. `russian_pages` собирает страницы. `without_code` гасит всё, что не проза:
  имя в обратных кавычках, блок кода, адрес ссылки, имя файла. Гасит пробелами на месте, поэтому
  номера строк не сдвигаются, а `pipeline` остаётся именем вещи. `jargon_self_check` проверяет
  словарь на образцах раньше, чем тот доберётся до страницы. Корень, потерявший букву, не находит
  ничего, и это выглядит точно как порядок в репозитории.
- **Жаргон в исходниках.** Справка команды и её сообщения уходят прямо в терминал, а написаны
  они в исходниках. `source_jargon_problems` читает файлы, которые назвал репозиторий, – у этих
  трёх это один каталог сообщений на каждый, – и судит строковые литералы с кириллицей.
  Английская половина каталога остаётся как есть, а с ней ключ сообщения, латинские имена и
  подстановка `{path}`. Литералы достаёт `russian_strings` через `ast`, так же как читаются
  соглашения выше. Поиск по тексту нашёл бы `"пин"` в строке, где написано `"пин" "гвин"`, и
  пропустил бы слово, разорванное между двумя строками. `source_findings` судит один файл.
  Названный исходник, которого нет на месте, – находка сама по себе: иначе переименованный
  каталог оставит проверку без текста, и она пройдёт молча.
- **`run` и `report`.** `run` зовёт все проверки, собирает их находки и отдаёт список `report`,
  а тот печатает его и отвечает кодом возврата, который читает CI. Упавшая проверка сама
  становится находкой, поэтому поломка сторожа не может прочитаться как "проблем нет".

## Сторожит себя

Пакет наведён на собственный README. `python scripts/check_docs.py` судит раздел выше так же,
как сторож потребителя судит его таблицу инструментов: каждое публичное имя из `__all__` названо
в обоих изданиях, и ни одно издание не называет исчезнувшего. Заодно судятся строки установки.
Тег, который они закрепляют, обязан быть версией, о которой сообщает пакет, иначе подъём версии
оставит потребителям адрес прошлого выпуска. Проверка идёт в CI на каждый push, и то же самое
утверждает набор тестов. Новая функция попадает в `main` только вместе с двумя строчками,
которые сообщают читателю, что она есть.

Жаргон сторож ищет и у себя. `python scripts/check_docs.py` читает русское издание словарём
`JARGON` и тем же заходом проверяет сам словарь на образцах. Слова словаря в тексте выше взяты
в обратные кавычки, иначе сторож нашёл бы их здесь. Перечень выше он сверяет со словарём в обе
стороны. Строка, убранная или добавленная только в коде, валит проверку, пока перечень не
поправят в обоих изданиях. Ненужную строку репозиторий выключает по имени: `allow=("хук",)`.

Соглашения, которые пакет раздаёт, он соблюдает и сам. Собственный набор тестов запускает
`process_encoding_problems` по `docsguard`, `tests` и `scripts`, а `text_write_newline_problems`
по `docsguard` и `scripts`, по тем двум, чьи записи переживают запуск.

Дыра, ради которой это написано, была собственной дырой пакета. Функция жила здесь и не была
названа ни в одном издании README, пока три репозитория ставили пакет, чтобы он рассказывал им
ровно про такое.
